# Koemieru MVP: 要件定義

Issue: [#1](https://github.com/satoryu/koemieru/issues/1)

## Problem Statement（解決したい課題）

Koemieruのゴールは、ブラウザのタブで再生されている音声を読めるテキストに変換し、ユーザーが動画・ポッドキャスト・会議の録音などを聞きながら他のタブで普通に作業を続けられるようにすることです。この体験はまだ何も実装されておらず、リポジトリは未改変のWXTスターターテンプレートのままです。このMVPでは最初のエンドツーエンドの機能を実装します：タブの音声をキャプチャし、OpenAIでほぼリアルタイムに文字起こしし、サイドパネルに継続的に更新される文字起こしを表示します。

## Requirements（要件）

### Functional（機能要件）

- サイドパネルで、ユーザーが自分自身のOpenAI APIキーを入力・保存（BYOK: Bring Your Own Key）でき、文字起こしの開始・停止、現在のステータス、リアルタイムの文字起こしを確認できる。
- 文字起こしを開始すると、その時点でユーザーがいるタブの音声をキャプチャし、その後ユーザーが他のタブに切り替えてもそのタブがキャプチャ対象であり続ける。
- キャプチャ対象のタブの音声は、ユーザーに聞こえ続ける（キャプチャによってタブがミュートされてはならない）。
- 音声は個別のファイルに分割するのではなく、OpenAI Realtime APIへ継続的にストリーミングする。
- 文字起こしエリアは確定したテキストを重複なく継続的に追記し、ユーザーが下端からスクロールして離れていない限り自動的に最新テキストに追従する。
- 文字起こしを停止すると、タブキャプチャ・OpenAI接続・音声リソースがすべてクリーンに解放される。その後、拡張機能を再読み込みせずに新しいセッションを開始できる。

### Non-Functional（非機能要件）

- バックエンドフリー：このMVPではKoemieru独自のサーバーコンポーネントを持たない（この選択がOpenAI認証にもたらすトレードオフはConstraintsを参照）。
- OpenAI APIキーは、リポジトリにコミットされない、ログに出力されない、OpenAI Realtimeエンドポイント以外のどこにも送信されないこと。
- `chrome.tabCapture`や`chrome.offscreen`など拡張機能特有のAPIに依存するコードは、その周辺の純粋ロジック（音声変換、文字起こしのマージ、メッセージプロトコル）がフェイク/モックを介して単体テストできるように設計する（CLAUDE.md準拠）。
- 実装は小さく理解しやすい状態を保つ — このMVPは一つの体験を検証するものであり、プラットフォームを作るものではない。

## Constraints（制約）

- **Manifest V3 / `chrome.tabCapture`**: タブ音声のキャプチャには、ユーザー操作のコンテキスト（サイドパネル）でストリームIDを発行し、それを`chrome.offscreen`ドキュメント内で引き換える必要がある。これはMV3のバックグラウンドサービスワーカーが（約30秒で）アイドルキルされ、DOM/Web Audioにアクセスできないためである。パイプライン全体は[design.md](design.md)を参照。
- **OpenAI Realtime APIの認証**: OpenAIの現行ドキュメントでは、ブラウザクライアントからの接続はWebRTC・WebSocketいずれの経路でも、サーバー側で発行するエフェメラルトークン（`POST /v1/realtime/client_secrets`）による認証のみが公式にサポートされている。このMVPではそれでもあえてバックエンドフリーを維持することを選択した：オフスクリーンドキュメントが`openai-insecure-api-key.<KEY>`というWebSocketサブプロトコルを使い、ユーザー自身の生のAPIキーで直接接続する。この仕組み自体はOpenAIのドキュメントに存在するが、例示コードでは常にエフェメラルトークンとペアで使われており、標準キーとの組み合わせでは一度も示されていない。この点はプロジェクトオーナーに明示的に提示し、既知のリスクとして了承済み（OpenAI側が予告なくこの組み合わせを拒否・破壊する可能性がある）。破綻した場合のフォールバックは、必要になった時点で導入する最小限のエフェメラルトークン発行バックエンドとする。
- **pnpm**をパッケージマネージャとして使用する（README/CLAUDE.mdの方針に準拠）。

## Acceptance Criteria（受け入れ基準）

- [ ] 拡張機能がビルドでき（`pnpm build`）、Chromeにパッケージ化されていない拡張機能として読み込める。
- [ ] ツールバーアイコンからサイドパネルが開き、APIキーを入力するとパネルの開閉をまたいでローカルに保存され続ける。
- [ ] 音声が再生されているタブで文字起こしを開始すると、そのタブの音声を可聴性を保ったまま継続的にキャプチャできる。
- [ ] 他のタブに切り替えても文字起こしは止まらない。
- [ ] 文字起こしテキストが重複なくサイドパネルに継続的に表示される。
- [ ] 停止するとキャプチャ・WebSocket・音声リソースがクリーンに解放され、拡張機能を再読み込みせずに次のセッションを開始できる。
- [ ] キャプチャ権限が拒否された場合、およびキャプチャ対象タブが閉じられた場合の両方で、サイレントに失敗せず明確なステータスが表示される。
- [ ] OpenAIとの接続が切れた場合も、サイレントに失敗せず明確なエラーステータスが表示される。
- [ ] 下記の約30分の検証シナリオに耐える。

## User Stories（ユーザーストーリー）

- ポッドキャストを1つのタブで聞いているユーザーとして、Koemieruを開いてOpenAI APIキーを一度入力し、Startをクリックするだけで、タブを離れたり再生を中断したりせずにリアルタイムの文字起こしを得たい。
- 文字起こしを開始したユーザーとして、自由に他のタブへ切り替えて作業を続けたい。文字起こしのために音声タブに留まることを強制されたくない。
- ユーザーとして、キャプチャ開始後も元のタブの音声が普通に再生され続けてほしい。文字起こし開始によって聞いていた音声が無音になるべきではない。
- ユーザーとして、キャプチャ権限が拒否された時、キャプチャ中のタブが閉じられた時、OpenAIとの接続が切れた時に、何が起きたか分かる明確なメッセージが欲しい。文字起こしが静かに止まったまま気づかない、という状況は避けたい。
- ユーザーとして、拡張機能を再読み込みせずに文字起こしを停止し、後で新しいセッションを開始したい。それによってKoemieruが通常のブラウジングセッションを通して信頼できるものだと感じたい。

## Target Validation Scenario（検証シナリオ）

1. 1人が主に話している、約30分の動画またはポッドキャストのタブを開く。
2. Koemieruの文字起こしを開始する。
3. 別のタブに切り替えて通常通り作業する。元の音声は再生したままにしておく。
4. その間、文字起こしがサイドパネルに継続的に表示され続けることを確認する。
5. 約30分間継続した後、文字起こしを通常通り停止する。
6. 以下を確認する：キャプチャが安定していたこと、接続が維持されていた（あるいはサイレントではなく可視の形で失敗した）こと、文字起こしが重複なく継続していたこと、タブ切り替えで何も壊れなかったこと、元の音声が聞こえ続けていたこと、停止時にリソースがクリーンに解放されたこと。

ライブ音声に対する文字起こしの多少の遅延は許容範囲とする。

## Out of Scope（対象外）

用語検出・用語解説、要約、翻訳、文字起こしの検索、セッションをまたいだ文字起こしの永続化・履歴、話者分離、ユーザーアカウント、APIキー以外の認証、課金、アナリティクス、Koemieru独自のバックエンド、クラウド同期、タブ以外のシステム全体の音声キャプチャ、Firefox/Safari対応、凝ったUI・アニメーション。
